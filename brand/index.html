explain like I'm five

You have a key and a locked box.

There is no clever metaphor. You put a note in a box, lock it with your friend's lock, and hand it to anyone willing to carry it. Only your friend can open it. The carrier never learns what is inside, or even who it is for.

01

Lock the box

Your friend's public key is the lock. Yours opens it. Nobody, including the app's author, holds both.

02

Hand it to a courier

A courier is a folder, a USB stick, or a little program. Arnauth ships one and you can write your own.

03

Forget what you don't use

People you stop talking to lose weight and fade out of your list. That is not a bug, it is the design.

what actually happens

Two locks, four keys, no server.

Each identity holds one seed. HKDF splits it into an Ed25519 key (who is speaking) and an X25519 key (who may listen). On top of both sits a post-quantum half: ML-DSA-65 for signatures, ML-KEM-768 for key agreement. Either pair alone is enough to reject a forgery.

Sealed messagesephemeral X25519 + ML-KEM-768 → HKDF → ChaCha20-Poly1305
Proof of senderEd25519 + ML-DSA-65 over the same bytes; both must verify
Tamper evidence at restidentity rows folded into a 32-byte 0x62-gated wupz frame
Files64 KiB chunks, content-addressed, resumable across restarts
Group chatsone key per cell; the body is sealed once, the key handed out per member
Broadcastone body, one envelope per recipient — never a shared key

Honest caveat. Off-chain messages are hybrid post-quantum. On-chain settlement is only as post-quantum as Ethereum is, which today means secp256k1 — not quantum-safe. We will say that on every page until it is untrue.

integrations

For systems, and for agents.

Two outward faces: signed webhooks for anything with an HTTP listener, and MCP for anything that thinks in tools. Plus plugins, which are just commands. 

# webhook: HMAC-SHA256 over the exact body
$ arnauth webhook add http://127.0.0.1:9000/hook \
    --event message.received

# every delivery carries
X-Arnauth-Signature: <hex hmac>
{"event":"message.received", ...}
# plugin: a command with the event on stdin
$ arnauth plugin add notifier \
    --command /usr/bin/say --arg "new message" \
    --event message.received

# agent: MCP over stdio, six tools
$ arnauth mcp

arnauth mcp exposes arnauth_whoami, arnauth_identities, arnauth_peers, arnauth_send, arnauth_inbox, arnauth_receipt. The tool process runs as you, so it is the credential — there is no token to leak.

how to

Three commands to a conversation.

# 1. you
$ arnauth quickstart kai.eth
$ arnauth card kai.eth > my-card.json

# 2. them (send my-card.json however you like)
$ arnauth trust my-card.json
# 3. talk
$ arnauth send kai.eth "hello"
$ arnauth send kai.eth --file photo.jpg
$ arnauth inbox --take --save ~/Downloads

# or open the window
$ arnauth-desktop

Lose key.bin and the identity is gone. No recovery, no escrow, no support desk. That is not an oversight — it is the only way "nobody can read it" stays true.
